============================================================
TELEMETRY & POWER DISTRIBUTION BOARD — REVAMP PLAN
============================================================

GOAL
----
Redesign the existing Telemetry and Power Distribution system
around a custom PCB.

The new board will act as a "motherboard", integrating simple
and reliable circuitry directly onto the PCB while keeping
complex, replaceable, or higher-risk components as modular
"daughterboards".


============================================================
1. OVERALL ARCHITECTURE
============================================================

MOTHERBOARD
-----------
Main custom PCB responsible for:

- Power distribution
- Current sensing
- Voltage sensing
- Battery cell monitoring
- Signal conditioning
- ADC protection/filtering
- Status / warning indicators
- Interconnection between modules
- Telemetry signal routing


DAUGHTERBOARDS / EXTERNAL MODULES
---------------------------------
Keep the following modular, at least for Rev. 1:

- Arduino Mega
- SD Card Module
- DC-DC Converters
- LCD Screen
- Temperature Sensors
- Buzzers

WHY?

- Easier replacement
- Easier troubleshooting
- Lower risk during initial development
- Allows proven commercial modules to remain in use
- A failure does not necessarily require replacing the entire PCB
- Individual modules can be upgraded later


============================================================
2. CIRCUITS TO INTEGRATE DIRECTLY INTO THE PCB
============================================================

The following should be redesigned and integrated directly:

[ ] Current Sensors
[ ] Voltage Sensors
[ ] Battery Cell Voltage Monitoring
[ ] Signal Conditioning
[ ] ADC Input Protection
[ ] RC Filtering
[ ] Status / Warning LEDs
[ ] Diagnostic Test Points

These circuits are relatively simple and can eliminate many
of the separate modules, wires, and connectors currently used.


IMPORTANT:

Research, prototype, and validate the DIY sensing and signal
conditioning circuits BEFORE integrating them into the final PCB.

Particular attention should be given to:

- Maximum input voltage
- Maximum current
- Arduino ADC voltage limits
- Voltage divider design
- Current sensor output range
- Input overvoltage protection
- RC filtering
- Noise
- Grounding
- Component tolerances
- Failure conditions


============================================================
3. BATTERY CELL MONITORING
============================================================

Redesign the existing battery cell monitoring / resistor board
as part of the motherboard.

Each cell measurement should include:

Battery Cell
    |
    +--> Voltage Scaling / Signal Conditioning
    |
    +--> Filtering
    |
    +--> ADC Protection
    |
    +--> Arduino Mega ADC


STATUS LEDs
-----------
Add visual indicators for battery condition.

Possible implementation:

GREEN  = Normal
YELLOW = Warning
RED    = Fault

Possible monitored conditions:

- Cell undervoltage
- Cell overvoltage
- Abnormal cell-to-cell voltage difference

Research whether these indicators should be controlled by:

A) Arduino Software

or

B) Independent hardware comparators

Hardware-controlled fault indicators could remain functional
even if the Arduino crashes.


============================================================
4. POWER DISTRIBUTION
============================================================

Keep compatibility with the rover's existing connector system:

INPUT / HIGH CURRENT:
- XT90 Male

OUTPUTS:
- XT60 Female


The motherboard should become the central power distribution
point.

Example:

                    BATTERY
                       |
                     XT90
                       |
                MAIN PROTECTION
                       |
               +-------+-------+
               |       |       |
              XT60    XT60    XT60
               |       |       |
             LOAD 1  LOAD 2  LOAD 3


DESIGN CONSIDERATIONS
---------------------

Determine:

[ ] Nominal system voltage
[ ] Maximum battery voltage
[ ] Continuous current
[ ] Peak current
[ ] Motor stall current
[ ] Expected fault current
[ ] Connector current ratings
[ ] Copper thickness
[ ] Required copper width / area
[ ] Fuse ratings
[ ] Thermal performance
[ ] Ground return paths


HIGH-CURRENT PCB DESIGN
-----------------------

Avoid treating high-current power paths like ordinary signals.

Use:

- Large copper pours / polygons
- Short power paths
- Appropriate copper thickness
- Multiple vias where current changes layers
- Proper connector placement
- Adequate thermal management

Keep high-current switching/power paths away from sensitive
analog telemetry signals whenever possible.


============================================================
5. PROTECTION
============================================================

Investigate adding protection directly to the motherboard.

Possible protections:

[ ] Main battery fuse
[ ] Individual output fuses
[ ] Reverse-polarity protection
[ ] Overvoltage protection
[ ] Transient suppression
[ ] Short-circuit protection
[ ] Overcurrent detection
[ ] Battery disconnect capability
[ ] Protected Arduino ADC inputs


IMPORTANT DESIGN PRINCIPLE:

The Arduino should MONITOR the system.

Critical protection should ideally NOT depend entirely on the
Arduino being alive and functioning correctly.


============================================================
6. BMS — FUTURE DEVELOPMENT
============================================================

Research replacing the existing battery monitoring/resistor
board with a true Battery Management System (BMS).


DESIRED BMS FEATURES
--------------------

[ ] Individual cell voltage monitoring
[ ] Cell balancing
[ ] Overcharge protection
[ ] Over-discharge protection
[ ] Charge cutoff
[ ] Overcurrent protection
[ ] Short-circuit protection
[ ] Temperature monitoring
[ ] Automatic battery disconnect during faults


POSSIBLE ARCHITECTURES
----------------------

OPTION A:
Integrate BMS directly into the motherboard.

OPTION B:
Design a dedicated custom BMS daughterboard.

OPTION C:
Use a commercial BMS and interface it with the motherboard.


RECOMMENDED APPROACH:

Do NOT make a fully custom BMS a requirement for Rev. 1.

Rev. 1 should prioritize:

1. Reliable Power Distribution
2. Reliable Voltage/Current Monitoring
3. Safe Signal Conditioning
4. ADC Protection
5. Modularity
6. Diagnostics

Develop the BMS separately once the core board is proven.

============================================================
CORE DESIGN PHILOSOPHY
============================================================

SAFETY
  >
RELIABILITY
  >
SERVICEABILITY
  >
MODULARITY
  >
COMPACTNESS


The objective is NOT simply to put everything onto one PCB.

The objective is to create a reliable central electrical
platform for the rover that is easy to monitor, diagnose,
repair, modify, and eventually expand.
